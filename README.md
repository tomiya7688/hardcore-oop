# Hardcore OOP

> Object-oriented programming on hardcore mode.

Hardcore OOP は、オブジェクト指向プログラミングに意図的に厳しい制約を課すためのルール仕様です。

目的は、責務・依存・公開範囲・配置・生成経路を明示し、コードベースの構造を可能な限り一意に読み取れる状態にすることです。

## バージョニング

Hardcore OOP では、**ルール仕様のバージョン**と**各種ツールのバージョン**を独立して管理します。

ツールのバージョン番号は、対応するルール仕様のバージョン番号と一致するとは限りません。

各ツールは、対応している Hardcore OOP ルール仕様のバージョンを明示しなければなりません。

現在のルール仕様: **v0.1.1**

## 基本思想

Hardcore OOP は、次の方向性を強制します。

- 1つのオブジェクトに1つの責務
- 1つのオブジェクトに1つの公開操作
- 1つの関数に1つの処理
- 同一スコープ内で同名の関数を定義しない
- 具象継承の禁止
- 依存関係の明示
- グローバル可変状態の排除
- Entry Point を根とする木構造の依存関係
- 循環依存の禁止
- 生成と実行の分離
- モデルの不変性

Hardcore OOP は、すべてのソフトウェアに対する普遍的なベストプラクティスを主張するものではありません。制約を強くすることで設計上の曖昧さを減らし、オブジェクト指向設計を意図的に極端な形で実践するための仕様です。
